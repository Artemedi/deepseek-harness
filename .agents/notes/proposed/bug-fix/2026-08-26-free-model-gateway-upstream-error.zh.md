# Agent Note: 保留免费模型网关错误

Status: proposed

[English](2026-08-26-free-model-gateway-upstream-error.md) | 中文

## 问题

通过免费模型网关路由的请求可能以 GUI 中的 `This turn failed` 结束，而唯一的诊断负载是 `{"type":"api_error","message":"Upstream error."}`。网关隐藏了提供方、HTTP 状态、稳定错误码、请求 ID 和可重试性，因此用户无法区分临时上游故障、被拒绝的请求和 DSH 传输故障。

这是网关／提供方错误报告问题，与 OpenViking 无关。OpenViking 可以提供持久上下文检索，但无法修复失败的模型请求或恢复网关丢失的诊断信息。

## 提案

端到端追踪免费模型路由，并让结构化上游错误依次穿过网关、API 传输、会话事件和 Web UI。最终诊断应保留提供方或路由身份、可用的 HTTP 状态、稳定错误码、可用的请求 ID、原始消息和可重试性分类，同时不得暴露凭据或授权头。

适用现有策略的临时网关和提供方故障应进入已有的重试或回退策略。pi-ai 适配器目前从最小网关负载只收到扁平的 `Upstream error.` 消息，因此会将这一精确消息分类为 `SERVER`；随后默认的有界重试策略可以恢复它。这只是临时 recovery classification，并不能替代保留提供方事实。永久故障应在轨迹和状态视图中保持可操作，并允许用户无需重新构造提示即可重试该轮次。

新增一个无需密钥的回放 fixture，覆盖仅包含当前 `api_error` 负载的网关响应，并覆盖结构化、可重试和永久上游故障。fixture 必须验证持久错误事实和渲染后的诊断。

## 考虑过的替代方案

- **保留字面消息 `Upstream error`。** 拒绝，因为它丢失了诊断、重试决策和支持报告所需的事实。

- **只修复 Web UI。** 拒绝，因为网关在客户端渲染前已经丢弃了信息；只改客户端无法恢复提供方状态或请求身份。

- **把所有网关故障都视为可重试。** 拒绝，因为认证、无效请求、配额和策略故障不应触发无限或误导性的重试。

- **使用 OpenViking 作为恢复机制。** 拒绝，因为上下文存储不提供传输诊断、提供方故障转移或请求重试语义。

## 接受标准

- 免费模型网关故障在网关提供结构化事实时，会将原始事实保留到会话日志和 Web UI。
- 只有 `api_error: Upstream error.` 的响应会被标记为网关上游故障，并在存在时显示请求关联 ID。
- 可重试和永久故障遵循不同且经过测试的策略，并且不会泄露秘密。
- 用户可以从现有会话状态重试失败的轮次。
- 无需密钥的组装 Web 测试覆盖最小负载和结构化网关错误。

## 风险

不同网关实现可能使用不同的错误负载，也可能省略请求 ID 或状态码。适配器必须保持稳定的 DSH 错误词汇，同时只以有界且脱敏的形式保留原始诊断。重试或回退可能重复执行提供方工作，因此幂等性和尝试次数必须保持显式。
